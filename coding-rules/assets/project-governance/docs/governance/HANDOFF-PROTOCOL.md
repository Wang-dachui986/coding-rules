# 交接协议

## 固定入口

```text
docs/handoffs/PROJECT.md
docs/handoffs/R0.md
docs/handoffs/R1.md
docs/handoffs/R2.md
docs/handoffs/R3.md
```

`PROJECT.md` 是全项目事实入口；角色文件记录当前角色批准范围、实现和下一步。

## 强制读取

每次开始获批任务，以及首次进入、上下文压缩、中断恢复、“继续/下一步”或
状态不确定时，重新读取 `AGENTS.md`、项目总交接、角色交接、当前获批任务
卡及其引用的合同、依赖、证据和审批文件。

## 强制更新

任务完成、部分完成、失败、阻塞、交给其他角色或可能中断前，更新角色交接。
R0 接受模块、改变总计划或完成集成时更新项目总交接。

## 写入要求

- 只写验证事实；推断明确标记。
- 记录批准范围、修改文件、实际验证、证据、清理和限制。
- `NOT_RUN`、`FAILED`、`BLOCKED` 和 `APPROVED_NOT_EXECUTED` 不得写成通过。
- 只引用脱敏证据路径，不复制原始秘密或日志。
- 下一步按执行顺序列出，并逐项标注审批状态。
- 新事实替代旧事实时保留必要原因，不无限累积聊天过程。

## 模块级接收与验收

- R1-R3 子任务完成只表示 `COMPLETED_MODULE_INPUT_READY`。
- R0 在子任务之间仅轻量核对任务卡/摘要、范围、交接、证据、依赖和高风险
  停止条件，不重跑全仓测试、完整构建或完整浏览器矩阵。
- 模块全部子任务、共享集成和必要运行表面完成后，R0 才执行一次系统性验收。
- 安全、秘密、数据破坏、真实产品阻断、合同冲突和越权修改立即停止并升级。

## 完成汇报

R1-R3 最终回复和角色交接只列出：完成内容、修改文件、实际验证与 `NOT_RUN`、
证据、阻塞/限制，以及“结果已返回 R0，等待接收或新任务卡”。不得规划下一
任务或报告项目总进度。R0 才汇报总进度、下一步顺序和逐项审批状态。当前
任务获批不自动授权下一项。

## R0 自动闭环

R1-R3 返回完成、失败或阻塞结果后，R0 自动执行轻量接收，更新 R0 和必要的
PROJECT 交接，并编制下一张修复卡或模块任务卡；无需单独询问是否制卡。
轻量接收不得重跑全量测试。新卡必须固定 ID、版本、范围、
`WAITING_APPROVAL` 状态和摘要，然后向项目所有者汇报并等待批准。未经批准
不得分发或执行；安全、秘密、数据破坏、真实产品阻断、越权和合同冲突仍须
立即升级。

## 冲突处理

交接与实现、任务卡或项目所有者最新指令冲突时停止执行，由 R0 根据最新
证据修正。任何角色不得凭记忆选择对自己有利的版本。
