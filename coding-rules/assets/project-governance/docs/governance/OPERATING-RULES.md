# 项目运行规则

- 生效状态：`ACTIVE`
- 项目所有者：`[待项目所有者确认]`
- 当前版本：`[待确认]`

## 目标

以可审批、可恢复、可验证和可交接的方式完成项目。结果优先于过程数量，
小功能完整闭环优先于多个半成品并行。

## 权威顺序

1. 项目所有者最新明确指令；
2. 根目录 `AGENTS.md`；
3. 已批准任务卡；
4. `docs/handoffs/PROJECT.md`；
5. 当前角色交接；
6. 其他计划和历史证据。

冲突时停止，由 R0 修正权威记录。

## 审批

治理初始化之外的修改、命令、测试、依赖、联网、Git、部署、服务器和外部
操作必须进入获批任务卡。讨论和解释可直接进行。审批不得由智能体互相代替。

## 执行

- 一个任务一个负责人，一个范围，一个验收结论。
- 先调查完整相关路径，再集中实现。
- R1-R3 先定向验证并交接，正常结果仅为模块输入就绪。
- R0 在子任务之间只做轻量接收，不重复完整测试、构建或浏览器矩阵。
- R1-R3 返回结果后，R0 自动轻量接收、更新 R0/PROJECT 交接并编制下一张
  `WAITING_APPROVAL` 任务卡；无需单独询问是否制卡。
- 全部子任务、共享集成和必要运行表面完成后，只做一次模块系统性验收。
- 失败时记录实际结果，不为获得绿色结果删除或弱化有效测试。
- 无法验证时写明原因和最接近的替代检查。
- 实际用户表面适用时必须进行手工 QA。

## 多对话

- R0 保持唯一总控。
- 首次调用 `$coding-rules` 时先复用已有 R1-R3，只为缺失角色各创建一个长期
  本地项目对话并设为 `IDLE`；禁止重复创建或用短期子智能体代替。
- 对话工具不可用或失败时标记 `NOT_CREATED`，提供三个可直接发送的角色提示
  词并如实报告，不得声称创建成功。
- 长期对话按稳定模块划分，不按每个小任务创建。
- R1-R3 只接收 R0 原样分发的获批任务卡。
- R1-R3 只执行、验证、更新本角色交接并返回事实；不规划、制卡、分发或更新
  项目总进度。
- 文件所有权不得重叠；共享文件由 R0 协调。
- 模块完成声明必须由 R0 基于文件、测试和证据独立接受。
- 分发前固定任务卡批准来源、状态、版本和摘要；内容变化不得静默沿用旧摘要。
- 分发前执行轻量只读冲突预检，核对工作区、接受基线、依赖、文件所有权、
  允许范围、验证和停止条件；代码影响优先使用 CodeGraph。
- 发现缺少权限、目标冲突、输入不足、活动写入重叠、验证不可行或已知停止
  条件时不得分发；先修订任务卡并重新固定版本/摘要。
- 只有 `READY_FOR_OWNER_APPROVAL` 预检和精确版本批准同时满足才能分发；
  预检不得运行全量测试或系统验收。
- 自动制卡后向项目所有者汇报并等待明确批准；未经批准不得分发或执行。
- 优先复用既有长期角色对话，并在工具可见时确认任务已接收或开始。

项目所有者日常只需在 R0 提出需求和审批；R0 自动规划、制卡、预检和分发，
R1-R3 只执行收到的获批任务卡。

## 完成汇报

R1-R3 最终回复和交接只包含本卡完成内容、修改文件、验证与未运行项、证据、
阻塞/限制和等待 R0。只有 R0 汇报项目总进度、规划下一步并标注审批状态。
当前批准不自动授权下一任务。

## 交付

- 区分源码、候选制品、部署版本和正式发布。
- 制品记录摘要、平台、测试和已知限制。
- 使用说明覆盖安装、使用、升级、回滚、卸载和排错。
- 未验证环境明确标记 `NOT_RUN`。

## 开发进度制品

- 项目需要开发进度表时，R0 是唯一维护者；R1-R3 只通过交接提交事实。
- 固定路径：`[待项目所有者确认]`。R0 每次任务闭环后更新相关功能、审批、
  更新日志、基准日期和总览。
- 进度表是报告视图，不替代任务卡、交接和系统验收证据。验收进度、计划估算
  和明细平均必须分开标注。
- 电子表格更新后检查关键区域、公式错误和所有变更工作表的视觉效果，并在
  R0/PROJECT 交接记录验证和摘要。
