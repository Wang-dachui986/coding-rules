# 工作流与角色

- 状态：`ACTIVE`

| 角色 | 默认职责 | 默认不承担 |
|---|---|---|
| R0 | 需求、审批、契约、任务卡、分发、集成、验收、总交接 | 未获批时替模块实现 |
| R1 | 核心业务、后端、数据和自动化测试 | 部署与视觉验收 |
| R2 | 平台、集成、部署、运维、安全边界 | 业务 UI |
| R3 | 前端、交互、文档表面和浏览器 QA | 后端数据与生产运维 |

## 当前项目映射

首次明确调用 `$coding-rules` 时，先复用已有 R1-R3，只为缺失角色各创建一个
长期项目对话并保持 `IDLE`；禁止重复创建。初始化以外启用新角色、创建长期
对话或改变所有权，仍必须由项目所有者批准并由 R0 更新本文件和当前任务表。

## 用户使用方法

项目所有者日常只需要在 R0 总控对话提出需求和审批。R0 自动规划、编制任务
卡、执行分发前冲突预检，并把获批任务分发给 R1-R3；项目所有者无需分别管理
三个执行对话。
